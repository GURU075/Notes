Open–Closed Principle (OCP)

Detailed Explanation with Examples – Interview Ready

1. What is the Open–Closed Principle?

The Open–Closed Principle states:

“Software entities (classes, modules, functions) should be open for extension, but closed for modification.”

This means you should be able to add new behavior to a system without changing existing, already tested code.

Key idea:
If adding a new feature forces you to edit old code → OCP is violated.

2. Why OCP is Important

  • Reduces regression bugs
  • Protects stable, tested code
  • Makes systems scalable
  • Improves maintainability
  • Supports clean architecture

3. OCP Violation Example (Wrong Design)

Problem: Payment processing using if-else logic 
class PaymentService {

    public void pay(String type, double amount) {

        if (type.equals("CARD")) {
            // card payment logic
        } else if (type.equals("UPI")) {
            // upi payment logic
        } else if (type.equals("NETBANKING")) {
            // net banking logic
        }
    }
}

Problems with this approach:

  • Every new payment method requires modifying this class
  • Growing if-else chain
  • High risk of bugs
  • Not closed for modification

4. OCP Compliant Design (Correct Way)

Solution: Use abstraction and polymorphism

Step 1: Create an Interface

interface PaymentMethod {
    void pay(double amount);
}

Step 2: Create Implementations

class CardPayment implements PaymentMethod {
    public void pay(double amount) {
        // card payment logic
    }
}

class UPIPayment implements PaymentMethod {
    public void pay(double amount) {
        // upi payment logic
    }
}

Step 3: High-Level Module Uses Abstraction

class PaymentService {

    private PaymentMethod paymentMethod;

    public PaymentService(PaymentMethod paymentMethod) {
        this.paymentMethod = paymentMethod;
    }

    public void process(double amount) {
        paymentMethod.pay(amount);
    }
}

Now, adding CryptoPayment or WalletPayment requires no change to PaymentService.

5. How OCP is Achieved

  • Interfaces / Abstract classes
  • Polymorphism
  • Strategy Pattern
  • Factory Pattern
  • Dependency Injection (Spring)

6. OCP in Spring Boot (Real World)

@Service
public class OrderService {

    private final PaymentGateway gateway;

    public OrderService(PaymentGateway gateway) {
        this.gateway = gateway;
    }
}

Spring injects different implementations at runtime. Business logic remains unchanged.

7. Common Mistakes with OCP

  • Overusing interfaces unnecessarily
  • Creating abstractions when change is unlikely
  • Confusing OCP with “never modify code”
Rule of thumb:
Apply OCP where future change is expected.

8. Interview-Ready Summary

The Open–Closed Principle ensures that software can grow without breaking existing functionality. It encourages extension through abstraction rather than modification of existing code.

In Java and Spring Boot, OCP is commonly implemented using interfaces, polymorphism, and dependency injection.
