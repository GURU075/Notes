Single Responsibility Principle (SRP)

Detailed Explanation with Examples – Interview Ready

1. What is the Single Responsibility Principle?

The Single Responsibility Principle (SRP) states:

“A class should have only one reason to change.”

This means a class should have only one responsibility, or in simple words, one job.

Key idea:
If a class changes for more than one reason → SRP is violated.

2. Why SRP is Important

  • Improves readability and clarity
  • Reduces side effects when changing code
  • Makes testing easier
  • Improves maintainability
  • Encourages clean architecture

3. SRP Violation Example (Wrong Design)

Problem: One class handling multiple responsibilities 
class UserService {

    public void registerUser() {
        // user registration logic
    }

    public void sendWelcomeEmail() {
        // email sending logic
    }

    public void logActivity() {
        // logging logic
    }
}

What’s wrong here?

  • User registration logic changes → class changes
  • Email logic changes → same class changes
  • Logging changes → same class changes
  • Multiple reasons to change → SRP violation

4. SRP Compliant Design (Correct Way)

Solution: Split responsibilities into separate classes

User Registration Responsibility

class UserService {

    public void registerUser() {
        // user registration logic
    }
}

Email Responsibility

class EmailService {

    public void sendWelcomeEmail() {
        // email sending logic
    }
}

Logging Responsibility

class AuditLogger {

    public void logActivity() {
        // logging logic
    }
}

Each class now has only one responsibility and one reason to change.

5. How SRP Helps in Real Projects

  • Changes are localized
  • Bug fixing becomes safer
  • Classes remain small and focused
  • Code reviews become easier

6. SRP in Spring Boot (Real-World Example)

@Service
public class OrderService {
    public void createOrder() {
        // order creation logic
    }
}

@Service
public class NotificationService {
    public void notifyUser() {
        // send notification
    }
}

@Service
public class PaymentService {
    public void processPayment() {
        // payment logic
    }
}

Each service handles a single responsibility. This is how SRP appears in clean Spring Boot applications.

7. Common Mistakes with SRP

  • God classes doing everything
  • Mixing business logic with infrastructure logic
  • Combining validation, persistence, and communication
Rule of thumb:
If a class description needs the word “and”, it violates SRP.

8. Interview-Ready Summary

The Single Responsibility Principle ensures that a class focuses on one task only. This reduces coupling, improves maintainability, and makes systems easier to understand.

9. One-Line Memory Hook

“One class, one job, one reason to change.”
