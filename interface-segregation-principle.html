Interface Segregation Principle (ISP)

Detailed Explanation with Examples – Interview Ready

1. What is the Interface Segregation Principle?

The Interface Segregation Principle (ISP) states:

“Clients should not be forced to depend on interfaces they do not use.”

In simple terms, instead of creating one large interface, we should create multiple small, specific interfaces.

Key idea:
If a class is forced to implement methods it doesn’t need → ISP is violated.

2. Why ISP is Important

  • Prevents unnecessary method implementations
  • Reduces coupling between classes
  • Makes code easier to understand
  • Improves maintainability
  • Prevents ripple effects when interfaces change

3. ISP Violation Example (Wrong Design)

Problem: Fat interface with unrelated methods 
interface Machine {
    void print();
    void scan();
    void fax();
}
    
class SimplePrinter implements Machine {

    public void print() {
        // printing logic
    }

    public void scan() {
        // not needed
    }

    public void fax() {
        // not needed
    }
}

Why this is wrong:

  • SimplePrinter does not need scan() or fax()
  • Empty or dummy implementations appear
  • Interface change affects all implementations
  • Violates ISP

4. ISP Compliant Design (Correct Way)

Solution: Split interfaces by responsibility 
interface Printer {
    void print();
}

interface Scanner {
    void scan();
}

interface Fax {
    void fax();
}
    
class SimplePrinter implements Printer {
    public void print() {
        // printing logic
    }
}
    
class MultiFunctionMachine implements Printer, Scanner, Fax {
    public void print() {}
    public void scan() {}
    public void fax() {}
}

Each class now implements only what it actually needs.

5. ISP and SRP – Important Difference

  • SRP → One responsibility per class
  • ISP → One responsibility per interface

SRP focuses on classes, ISP focuses on interfaces.

6. ISP in Java Standard Library

Set
Queue

Java does not provide one large Collection interface with all operations. Instead, it splits them into focused interfaces.

CrudRepository

You choose only what you need. Spring does not force pagination methods if you only need CRUD.

8. Common Mistakes with ISP

  • Creating god interfaces
  • Adding methods “just in case”
  • Forcing backward compatibility hacks
  • Mixing unrelated responsibilities
Rule of thumb:
If implementing an interface feels painful → interface is wrong.

9. Interview-Ready Summary

The Interface Segregation Principle ensures that interfaces remain small, focused, and client-specific. This prevents unnecessary dependencies and keeps systems flexible and easy to maintain.

10. One-Line Memory Hook

“Many small interfaces are better than one fat interface.”
