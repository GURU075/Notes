1. Big Picture

Spring Security is a system that sits before your controller and checks whether the current request should be allowed to continue.

It mainly answers 2 questions:

  • Who are you? → Authentication
  • Are you allowed to do this? → Authorization
Authentication Verifies identity. Example: username and password are correct, or JWT token is valid.
Authorization Checks permission after identity is known. Example: only ADMIN can access /admin/**.
SecurityContext Temporary place where Spring Security stores the currently authenticated user for the current request.
Main idea: Spring Security is easier when you study it as a request journey, not as random classes.

2. Authentication vs Authorization

Concept Question Example When it happens
Authentication Who are you? Checking username/password or validating JWT First
Authorization What can you access? Only users with role ADMIN can delete records After authentication

A user can be authenticated but still not authorized for some endpoints. Example: logged in successfully, but trying to access an ADMIN-only URL.

3. Full Request Flow

This is the mental model you should remember:

Request comes in
→
Security Filter Chain
→
Authentication check
→
SecurityContext set
→
Authorization check
→
Controller
→
Response

Simple analogy

Think of your backend like an office building.

  • The request is a person entering the building.
  • The filters are the security guards at the entrance.
  • Authentication checks identity card.
  • Authorization checks whether that person can enter a restricted room.
  • If everything is correct, the person reaches the controller.

4. Main Components and Their Roles

SecurityFilterChain Defines security rules: which URLs are public, which require authentication, session policy, filter order, and more.
AuthenticationManager Entry point for checking login credentials during username/password login.
UserDetailsService Loads user details from the database by username.
PasswordEncoder Encodes password during registration and compares passwords during login.
JwtUtil Generates JWT, validates JWT, and extracts username from JWT.
JwtAuthFilter Runs before controller, reads token from request header, validates it, and sets authentication in SecurityContext.
SecurityContextHolder Holds the authenticated user object for the current request.
UsernamePasswordAuthenticationToken Authentication object used both during login and after JWT validation.

5. Register Flow

POST /register
→
Controller
→
Service
→
PasswordEncoder.encode()
→
Repository.save()
→
User saved

Important point

During registration, you manually call passwordEncoder.encode(rawPassword) before saving the user. You should never store plain password in the database. 

// Register logic example
user.setUsername(request.getUsername());
user.setPassword(passwordEncoder.encode(request.getPassword()));
user.setRole("USER");
userRepository.save(user);

6. Login Flow

The most important login line is:

authenticationManager.authenticate(
    new UsernamePasswordAuthenticationToken(username, password)
);

When this line runs, Spring Security does the internal work:

POST /login
→
Controller
→
Service
→
AuthenticationManager
→
UserDetailsService.loadUserByUsername()
→
PasswordEncoder.matches()
→
Success
→
JWT generated

Most important understanding

  • You call AuthenticationManager.
  • Spring internally calls UserDetailsService.
  • Spring internally uses PasswordEncoder to compare passwords.
  • If successful, then you create and return JWT.

Why SecurityContext matters

After token validation, the filter creates an authentication object and stores it in SecurityContextHolder. This tells Spring Security that the request already has an authenticated user. 

SecurityContextHolder.getContext().setAuthentication(authenticationToken);

8. Important Methods and What They Mean

loadUserByUsername(String username)

  • Who calls it? Spring Security
  • When? During login or while rebuilding auth from token
  • Purpose: Fetch user from DB and convert it to UserDetails

passwordEncoder.encode(password)

  • When? During registration
  • Purpose: Hash the password before saving

authenticationManager.authenticate(...)

  • When? During login
  • Purpose: Ask Spring to verify username and password

jwtUtil.generateToken(username)

  • When? After successful login
  • Purpose: Create JWT token for future requests

doFilterInternal(request, response, filterChain)

  • Who calls it? Spring Security filter chain
  • When? For each incoming request
  • Purpose: Read and validate JWT before request reaches controller

filterChain.doFilter(request, response)

  • Meaning: Continue to next filter or controller
  • If omitted: request stops there

9. SecurityFilterChain Explained

@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/auth/register", "/auth/login").permitAll()
            .anyRequest().authenticated()
        )
        .sessionManagement(session -> session
            .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
        )
        .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);

    return http.build();
}
Code Meaning
csrf(csrf -> csrf.disable()) Disables CSRF for REST API style usage, especially common with JWT
requestMatchers(...).permitAll() These URLs can be used without login
anyRequest().authenticated() All other requests need authenticated user
SessionCreationPolicy.STATELESS Do not use HTTP session; JWT is stateless
addFilterBefore(...) Run custom JWT filter before Spring's username/password filter

10. Common Errors and Their Meaning

403 Forbidden Usually request reached Spring Security but was denied. Common reason: CSRF enabled or endpoint not permitted.
401 Unauthorized Authentication is missing or invalid. Example: token not sent or token invalid.
Invalid CSRF token Common in POST/PUT/DELETE when using default Spring Security without disabling CSRF for API learning project.
User not found loadUserByUsername() could not find the user in DB.
Bad credentials Username exists but password does not match encoded password in DB.
Expired JWT Token time limit is over; login again to get new token.
