1. Why Do We Need Data Mapping?

In Spring Boot applications, we should not directly expose database entities in API responses. We usually convert data between objects.

Request DTO → Entity → Database → Entity → Response DTO

Example

EmployeeRequest  -> EmployeeEntity
EmployeeEntity   -> EmployeeResponse
List<Employee>   -> List<EmployeeResponse>
Simple meaning: Mapping means converting data from one object to another object.

2. Manual Mapping First

Before learning MapStruct and ModelMapper, you should understand manual mapping.

public EmployeeResponse toResponse(Employee employee) {
    EmployeeResponse response = new EmployeeResponse();
    response.setId(employee.getId());
    response.setName(employee.getName());
    response.setEmail(employee.getEmail());
    return response;
}
Advantage: Full control and easy to debug.
Disadvantage: Repetitive when there are many DTOs and fields.

3. What is MapStruct?

MapStruct is a compile-time Java bean mapping library. You create a mapper interface, and MapStruct generates the implementation class during compilation.

How MapStruct Works

  1. You create an interface.
  2. You add @Mapper.
  3. MapStruct generates implementation at compile time.
  4. Spring injects the mapper bean.

Why It Is Good

  • Fast performance.
  • Compile-time safety.
  • No reflection.
  • Best for enterprise projects.

Maven Dependency

<dependency>
    <groupId>org.mapstruct</groupId>
    <artifactId>mapstruct</artifactId>
    <version>1.5.5.Final</version>
</dependency>

<dependency>
    <groupId>org.mapstruct</groupId>
    <artifactId>mapstruct-processor</artifactId>
    <version>1.5.5.Final</version>
    <scope>provided</scope>
</dependency>

Entity

public class Employee {
    private Long id;
    private String name;
    private String email;
    private Double salary;

    // getters and setters
}

Request DTO

public class EmployeeRequest {
    private String name;
    private String email;
    private Double salary;

    // getters and setters
}

Response DTO

public class EmployeeResponse {
    private Long id;
    private String name;
    private String email;

    // salary is not exposed in response
}

MapStruct Mapper

import org.mapstruct.Mapper;
import org.mapstruct.Mapping;
import java.util.List;

@Mapper(componentModel = "spring")
public interface EmployeeMapper {

    @Mapping(target = "id", ignore = true)
    Employee toEntity(EmployeeRequest request);

    EmployeeResponse toResponse(Employee employee);

    List<EmployeeResponse> toResponseList(List<Employee> employees);
}
componentModel = "spring" means MapStruct will generate the mapper implementation as a Spring Bean, so you can inject it using constructor injection.

Service Usage

@Service
@RequiredArgsConstructor
public class EmployeeService {

    private final EmployeeRepository employeeRepository;
    private final EmployeeMapper employeeMapper;

    public EmployeeResponse createEmployee(EmployeeRequest request) {
        Employee employee = employeeMapper.toEntity(request);
        Employee savedEmployee = employeeRepository.save(employee);
        return employeeMapper.toResponse(savedEmployee);
    }
}

Generated Code Concept

You do not write this code, but MapStruct generates similar code internally.

@Component
public class EmployeeMapperImpl implements EmployeeMapper {

    @Override
    public EmployeeResponse toResponse(Employee employee) {
        if (employee == null) {
            return null;
        }

        EmployeeResponse response = new EmployeeResponse();
        response.setId(employee.getId());
        response.setName(employee.getName());
        response.setEmail(employee.getEmail());
        return response;
    }
}

4. MapStruct When Field Names Are Different

If source and target field names are different, use @Mapping.

public class Employee {
    private String employeeName;
}

public class EmployeeResponse {
    private String name;
}
@Mapper(componentModel = "spring")
public interface EmployeeMapper {

    @Mapping(source = "employeeName", target = "name")
    EmployeeResponse toResponse(Employee employee);
}
Meaning: employee.employeeName will be mapped to response.name.

5. What is ModelMapper?

ModelMapper is a runtime object mapping library. It maps objects while the application is running. It mainly uses reflection and naming conventions.

How ModelMapper Works

  1. You create a ModelMapper bean.
  2. You call modelMapper.map(source, Target.class).
  3. It checks matching fields at runtime.
  4. It maps values automatically.

Why It Is Easy

  • Very less code.
  • Good for simple DTOs.
  • Quick for demo or small project.
  • Works well when field names are same.

Maven Dependency

<dependency>
    <groupId>org.modelmapper</groupId>
    <artifactId>modelmapper</artifactId>
    <version>3.2.0</version>
</dependency>

Spring Boot Configuration

@Configuration
public class ModelMapperConfig {

    @Bean
    public ModelMapper modelMapper() {
        return new ModelMapper();
    }
}

Service Usage

@Service
@RequiredArgsConstructor
public class EmployeeService {

    private final ModelMapper modelMapper;
    private final EmployeeRepository employeeRepository;

    public EmployeeResponse createEmployee(EmployeeRequest request) {
        Employee employee = modelMapper.map(request, Employee.class);
        Employee savedEmployee = employeeRepository.save(employee);
        return modelMapper.map(savedEmployee, EmployeeResponse.class);
    }
}
Important: ModelMapper is simple, but for complex enterprise mapping, debugging can become difficult because mapping happens at runtime.

6. ModelMapper With Different Field Names

When field names are different, you need custom configuration.

public class Employee {
    private String employeeName;
}

public class EmployeeResponse {
    private String name;
}
TypeMap<Employee, EmployeeResponse> typeMap =
        modelMapper.createTypeMap(Employee.class, EmployeeResponse.class);

typeMap.addMapping(Employee::getEmployeeName, EmployeeResponse::setName);
Problem: For many complex mappings, ModelMapper configuration can become less readable compared to MapStruct.

7. MapStruct vs ModelMapper

Point MapStruct ModelMapper
Mapping Time Compile time Runtime
Internally Uses Generated Java setter/getter code Reflection and conventions
Performance Faster Slower compared to MapStruct
Error Detection Compile-time errors Runtime errors possible
Debugging Easy, generated code can be checked Harder in complex scenarios
Best For Enterprise and production projects Small apps, demos, simple DTOs
Code Style Interface based Object method call based
Recommendation: For interviews and enterprise Java projects, prefer MapStruct. Understand ModelMapper also, but make MapStruct your main answer.

8. Nested Object Mapping

Nested mapping is very common in real projects.

public class Employee {
    private Long id;
    private String name;
    private Department department;
}

public class Department {
    private Long id;
    private String name;
}

public class EmployeeResponse {
    private Long id;
    private String name;
    private String departmentName;
}

MapStruct Nested Mapping

@Mapper(componentModel = "spring")
public interface EmployeeMapper {

    @Mapping(source = "department.name", target = "departmentName")
    EmployeeResponse toResponse(Employee employee);
}

ModelMapper Nested Mapping

modelMapper.typeMap(Employee.class, EmployeeResponse.class)
        .addMappings(mapper -> {
            mapper.map(src -> src.getDepartment().getName(),
                       EmployeeResponse::setDepartmentName);
        });
Observation: For nested mapping, MapStruct is usually cleaner and more readable.

9. Partial Update Mapping

In update APIs, do not blindly create a new entity from request. First fetch existing entity, then update it.

Bad Approach

Employee employee = employeeMapper.toEntity(request);
employee.setId(id);
employeeRepository.save(employee);
Why bad? Existing values can become null, audit fields can be lost, and relationships can break.

Good MapStruct Approach

@Mapper(componentModel = "spring")
public interface EmployeeMapper {

    @BeanMapping(nullValuePropertyMappingStrategy = NullValuePropertyMappingStrategy.IGNORE)
    void updateEmployeeFromRequest(EmployeeUpdateRequest request,
                                   @MappingTarget Employee employee);
}

Service Usage

public EmployeeResponse updateEmployee(Long id, EmployeeUpdateRequest request) {
    Employee employee = employeeRepository.findById(id)
            .orElseThrow(() -> new RuntimeException("Employee not found"));

    employeeMapper.updateEmployeeFromRequest(request, employee);

    Employee updatedEmployee = employeeRepository.save(employee);
    return employeeMapper.toResponse(updatedEmployee);
}
Meaning: If request field is null, MapStruct will not overwrite the existing entity field.

10. Common Mistakes in Data Mapping

1. Exposing Entity Directly

// Bad
@GetMapping("/{id}")
public Employee getEmployee(@PathVariable Long id) {
    return employeeRepository.findById(id).get();
}
Entity may expose sensitive fields. Entity should not become your API contract. 
// Good
@GetMapping("/{id}")
public EmployeeResponse getEmployee(@PathVariable Long id) {
    return employeeService.getEmployee(id);
}

2. Mapping Inside Controller

Controller should only receive request and return response. Mapping should be in mapper layer or service layer through mapper.

3. Blindly Mapping ID from Request

@Mapping(target = "id", ignore = true)
Employee toEntity(EmployeeRequest request);

4. Not Handling Null Values During Update

For PATCH/update APIs, use NullValuePropertyMappingStrategy.IGNORE to avoid overwriting existing values with null.

11. Interview Answers

Q1. What is MapStruct?

Answer: MapStruct is a compile-time Java bean mapping library. We define mapper interfaces and MapStruct generates implementation classes during compilation. It maps DTOs to entities and entities to DTOs using generated getter/setter code. It is faster and safer than reflection-based mappers, so it is preferred in enterprise applications.

Q2. What is ModelMapper?

Answer: ModelMapper is a runtime object mapping library. It maps one object to another using reflection and naming conventions. It is easy to use when source and target fields have the same names, but complex mappings can become harder to debug.

Q3. Difference between MapStruct and ModelMapper?

Answer: MapStruct performs mapping at compile time by generating Java code, while ModelMapper performs mapping at runtime using reflection. MapStruct is faster, type-safe, and better for enterprise projects. ModelMapper is easier to start with but less predictable in complex scenarios.

Q4. Why should we not expose Entity directly?

Answer: We should not expose entity directly because it may contain sensitive fields, lazy-loaded relationships, internal database structure, and audit fields. DTOs help us control what data is accepted in request and what data is returned in response.

Q5. How do you handle partial update using MapStruct?

Answer: First, we fetch the existing entity from the database. Then we use MapStruct with @MappingTarget to update the same entity. For PATCH APIs, we use NullValuePropertyMappingStrategy.IGNORE so null request fields do not overwrite existing values.

- Uses reflection
- Very easy to start
- Good for simple DTOs
